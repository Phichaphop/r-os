## ข้อจำกัดที่รู้แล้ว (ผ่านบางส่วน)
1. **บัญชีเป็น Demo เท่านั้น (DEC-50):** `finance.activation = demo_only` — ผังบัญชี กฎแปลงบัญชี และงวดทั้งหมดเป็นตัวอย่าง DEMO1 เงินเดือน (`payment.payroll.paid`) ไม่ได้ใส่กฎให้โดยตั้งใจ จะ "ต้องดำเนินการ" จนผู้ทำบัญชีกำหนด
2. **Finance Core ขั้นต่ำ:** มีสมุดรายวัน งวด งบทดลอง — ยังไม่มี AP/AR เต็ม งบการเงิน ภาษีซื้อ/ขาย หรือกระทบยอดธนาคารรายบรรทัด
3. **ยังไม่เลือกธนาคาร:** ไฟล์โอนเป็นรูปแบบกลาง ต้องเพิ่ม adapter เมื่อทราบธนาคาร · การจับคู่ผลธนาคารใช้เลขบัญชี + จำนวนเงิน — ถ้าบัญชีเดียวมีหลายรายการยอดเท่ากันในชุดเดียว ระบบจับคู่ตามลำดับแถว (ไม่ซ้ำรายการ) ซึ่งถ้ามีรายการหนึ่งสำเร็จอีกรายการล้มเหลว อาจจับคู่สลับกันได้ ควรหลีกเลี่ยงหรือตรวจด้วยตาจนกว่าจะมีเลขอ้างอิงของธนาคาร
4. **ตัวจัดตารางงานยังเป็นแบบ piggyback** (ทำงานหลังเปิดหน้า) — มี endpoint `POST /m2m/scheduler/run` + กุญแจ HMAC พร้อมสำหรับ cron ภายนอก แต่ยังไม่ได้ตั้ง
5. **การกู้คืนทำในคำขอเว็บ** (ทีละขั้น) — ฐานข้อมูลใหญ่บนโฮสต์ฟรีอาจชนเวลาจำกัด ควรใช้ CLI/โฮสต์จริงในอนาคต
6. **ZIP ไม่รองรับ ZIP64** → ไฟล์สำรองต้องไม่เกิน 4 GB
7. **ไม่มีสำเนานอกเครื่อง:** ไฟล์สำรองอยู่โฟลเดอร์เดียวกับโฮสต์จนกว่าจะตั้ง `BACKUP_OFFSITE_PATH` หรือดาวน์โหลดเก็บเอง — **APP_KEY ต้องเก็บแยกจากไฟล์สำรอง** ถ้าหาย กู้คืนไม่ได้
8. **MFA ยังปิดเป็นค่าเริ่มต้น** (DEC-52) — ข้อเสนอให้เป็นเงื่อนไขของ Activation Gate ยังรอยืนยัน
