# รายงานผลทดสอบ — 0.45.0 (R7): ระดับความรุนแรง สายแจ้งเหตุ และแบบฟอร์มความปลอดภัย

```
Release: 0.45.0   Environment: Local (เครื่องพัฒนาของ AI) + ระบบติดตั้ง blue_fresh7 (อัปเดตด้วย migration)   วันที่: 2026-11-19
ผู้ทดสอบ: AI (Claude)   ผู้ตรวจ: — (รอเจ้าของระบบ UAT และผู้ทำหน้าที่ด้านความปลอดภัยของบริษัท)
เครื่องมือ: PHP 8.3 · MariaDB · PHPUnit 9.6.17 · PHPStan 1.12 · PHPCS 3.10 · Chromium (Playwright, CSP เปิดจริง) + axe-core 4.10
```

> **ที่มา:**
> - แผน DEC-103 / DEC-110: R7 = ระดับความรุนแรงและแบบฟอร์มความปลอดภัย
> - Q-14 "ยังไม่มี จป. วิชาชีพ — AI ร่างมาตรฐาน/แบบฟอร์ม"
> - Q-26 "AI กำหนดระดับความรุนแรง/สายแจ้งเหตุเริ่มต้น"
> - บันทึกการตัดสินใจ DEC-114

> **สำคัญ:** ข้อความระดับความรุนแรง สายแจ้งเหตุ จำนวนนาที ระดับความเสี่ยง และแบบฟอร์มทั้งหมด **ร่างโดย AI — ต้องตรวจก่อนใช้**
> - เป็นมาตรฐานภายในบริษัท ไม่ใช่ข้อกำหนดตามกฎหมาย ไม่ใช่แบบฟอร์มทางราชการ และไม่ได้อ้างมาตรากฎหมายใด
> - หน้าที่ตามกฎหมาย (เช่น การแจ้งหน่วยงานรัฐเมื่อเกิดเหตุร้ายแรง) ต้องตรวจกับผู้เชี่ยวชาญหรือหน่วยงานเอง

## ข้อควรรู้
- **สายแจ้งเหตุและการยกระดับทำงานเมื่อเผยแพร่นโยบายแล้วเท่านั้น** ก่อนเผยแพร่ การแจ้งเหตุทำงานแบบเดิม (ทีมความปลอดภัย + ผู้ที่ตั้งไว้ในหน้าตั้งค่า) ส่วนแบบฟอร์มพิมพ์ใช้ข้อความจากร่าง AI และบอกไว้บนหน้า
- **การยกระดับต้องมีงานตามเวลา** (cron `php bin/blue jobs:run` ทุกนาที หรือตัวเรียกงานแบบ piggyback บน InfinityFree) ถ้าตั้งได้แค่ทุก 15 นาที การยกระดับจะช้าได้สูงสุดเท่านั้น
- **"หัวหน้าสายงาน"** มาจากข้อมูลผู้บังคับบัญชาในทะเบียนพนักงาน ถ้าผู้แจ้งไม่มีหัวหน้าในระบบ หรือแจ้งแบบไม่ระบุชื่อ ระบบข้ามขั้นนี้ (ทีมความปลอดภัยยังได้รับเสมอ)
- **"ผู้บริหาร"** = ผู้มีสิทธิ์ `safety.approve` ที่มีบทบาท EXE · **"HR"** = ผู้มีสิทธิ์ดูข้อมูลการรักษา (`safety.medical`)
- **ใบสอบสวนไม่มีข้อมูลการรักษา** และเป็นเอกสารภายใน ควรเก็บเป็นความลับ
- แบบฟอร์มกระดาษใช้เมื่อเข้าระบบไม่ได้ ข้อมูลที่เขียนต้องนำเข้าระบบโดยเร็ว · ไม่มีการเก็บลายเซ็นที่วาดบนเซิร์ฟเวอร์
