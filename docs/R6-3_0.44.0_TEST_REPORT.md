## ข้อควรรู้
- **ข้อจำกัดของความนิรนาม:**
  - ระบบป้องกันได้ในระดับแอป: ผู้รับเรื่อง ผู้บริหาร และผู้ดูแลระบบในหน้าจอ ไม่เห็นผู้ส่ง
  - ระบบป้องกันไม่ได้:
    - **access log ของเว็บเซิร์ฟเวอร์/โฮสต์** ที่บันทึก IP และเวลาของทุกคำขอ
    - ผู้ที่ถือทั้งกุญแจเซิร์ฟเวอร์และฐานข้อมูล ถ้าผู้ส่งติ๊ก "เรื่องของฉัน" หรือในวันเดียวกับที่ส่ง (ตัวนับรายวัน)
    - เนื้อหาที่ผู้ส่งเขียนเอง
  - ถ้าต้องการความนิรนามสูงสุด ให้ติดตามจากอุปกรณ์ส่วนตัวที่หน้าสาธารณะ และไม่ติ๊ก "เรื่องของฉัน"
  - ควรตั้งโฮสต์ไม่ให้เก็บ access log ของ `/complaints` และ `/speak-up/`
- **การแจ้งผู้รับเรื่องช้าหนึ่งวันโดยตั้งใจ:** เรื่องอันตรายหรือเร่งด่วนต้องใช้ช่องทางฉุกเฉินของบริษัท (หน้าส่งเรื่องเขียนไว้)
- **ก่อนเปิดรับเรื่อง:**
  - ต้องมีประกาศกลุ่มผู้ร้องเรียน
  - ต้องมี CMP อย่างน้อย 2 คน
  - ผู้มีความรู้ด้านกฎหมายต้องตรวจนโยบายคุ้มครองผู้ร้องเรียนแล้ว โดยระบบบันทึกชื่อและวันที่ไว้
  - แนะนำให้มี CMX เป็นช่องทางสำรอง
- **ค่าที่ไม่มีค่าเริ่มต้น (บริษัทกำหนดเอง):** กำหนดตอบรับ กำหนดสรุปผล ระยะเก็บ และข้อความนโยบาย
- **บริษัทตัวอย่าง:** มอบ CMP ให้ hr.head1 และ safety.demo1 · มอบ CMX ให้ exec.demo1
- **ยังไม่มี:**
  - แนบเอกสาร PDF แบบลบ metadata
  - ส่งออก Excel
  - มอบหมายผู้ตรวจสอบหลายคน
  - เชื่อมกับเหตุความปลอดภัย (M39)
