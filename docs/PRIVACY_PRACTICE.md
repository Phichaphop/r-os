# แนวปฏิบัติความเป็นส่วนตัวของบริษัท (โครงมาตรฐาน)

> **ร่างโดย AI — ต้องตรวจก่อนใช้** · เอกสารนี้เป็นโครงให้บริษัทที่ยังไม่มีเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO) ใช้เริ่มงาน (Q-08, Q-13 · DEC-109) ไม่ใช่คำแนะนำทางกฎหมาย
> ทุกจำนวนวัน ระยะเวลา ฐานทางกฎหมาย และข้อความที่ใช้แจ้งบุคคลภายนอก ต้องให้ผู้มีความรู้ด้านกฎหมายคุ้มครองข้อมูลส่วนบุคคลตรวจและกำหนดก่อนใช้จริง ระบบ Blue OS ไม่มีค่าตั้งต้นสำหรับสิ่งเหล่านี้

## 1. บทบาท
| บทบาท | ในระบบ | หน้าที่ |
|---|---|---|
| เจ้าหน้าที่ความเป็นส่วนตัว (อย่างน้อย 2 คน) | บทบาท PRV | ดูแลศูนย์ความเป็นส่วนตัว: ประกาศ, ทะเบียนกิจกรรมการประมวลผล, เหตุละเมิดข้อมูล, คำขอเจ้าของข้อมูล · คนหนึ่งร่าง อีกคนอนุมัติ |
| ผู้มีความรู้ด้านกฎหมาย (ภายในหรือที่ปรึกษา) | — | ตรวจข้อความประกาศ ฐานทางกฎหมาย ระยะเก็บ และกำหนดเวลาตามกฎหมาย ก่อนเจ้าหน้าที่ PRV กดอนุมัติ |
| เจ้าของข้อมูลของแต่ละงาน | หัวหน้าฝ่ายที่ใช้โมดูลนั้น | บอกว่าเก็บอะไร เพื่ออะไร ใครเห็น เก็บนานแค่ไหน · แจ้งเมื่อเปลี่ยนวิธีทำงาน |
| ผู้ดูแลระบบ | บทบาท SYS | สิทธิ์ สำรองข้อมูล บันทึกตรวจสอบ — **ไม่ใช่ผู้ตัดสินเรื่องความเป็นส่วนตัว** |

## 2. งานที่ต้องทำก่อนใช้ข้อมูลจริง
1. แต่งตั้งเจ้าหน้าที่ PRV อย่างน้อย 2 คน (คนร่างกับคนอนุมัติต้องเป็นคนละคน)
2. ศูนย์ความเป็นส่วนตัว → **ทะเบียนกิจกรรมการประมวลผล**: กด "สร้างร่างจากโมดูลที่เปิดใช้" แล้วแก้ทุกรายการให้ตรงกับการทำงานจริง (วัตถุประสงค์ ฐานทางกฎหมาย ข้อมูล ผู้รับ ระยะเก็บ) → ให้ผู้มีความรู้ด้านกฎหมายตรวจ → เปิดใช้
3. ศูนย์ความเป็นส่วนตัว → **ประกาศความเป็นส่วนตัว**: สร้างร่างของแต่ละกลุ่ม (พนักงาน ผู้สมัครงาน ผู้มาติดต่อ ผู้ร้องเรียน ผู้ใช้ลงเวลา GPS ผู้รับเหมา) → แก้ข้อความ → ผู้มีความรู้ด้านกฎหมายตรวจ → อีกคนอนุมัติและเผยแพร่
4. กำหนดค่าที่เป็นข้อกำหนดทางกฎหมายในหน้าค่ากำหนด (ไม่มีค่าตั้งต้น): จำนวนวันตอบคำขอเจ้าของข้อมูล (`privacy.dsr_response_days`) และกำหนดเวลาประเมิน/แจ้งเหตุละเมิด (`privacy.breach_notify_hours`)
5. อนุมัติกฎระยะเก็บรักษาในหน้าการเก็บรักษาข้อมูล (ร่างของ AI ไม่มีผลจนกว่าจะอนุมัติ)
6. ตรวจผู้ประมวลผลภายนอก (โฮสต์ อีเมล ที่เก็บสำรองข้อมูล ผู้ให้บริการแผนที่) และบันทึกในทะเบียนการเชื่อมต่อ

## 3. งานประจำ
| ความถี่ | งาน | ที่ไหนในระบบ |
|---|---|---|
| ทุกวันทำงาน | ดูคำขอเจ้าของข้อมูลและเหตุละเมิดที่เปิดอยู่ | `/privacy/requests`, ศูนย์ความเป็นส่วนตัว → เหตุละเมิด |
| ทุกเดือน | ตรวจการรับทราบประกาศของพนักงาน · ตามคนที่ค้าง | ศูนย์ความเป็นส่วนตัว → ประกาศ → รายชื่อรับทราบ |
| เมื่อเปิดโมดูลใหม่หรือเปลี่ยนวิธีทำงาน | เพิ่ม/แก้กิจกรรมในทะเบียน · ทบทวนประกาศที่เกี่ยวข้อง | ทะเบียนกิจกรรม |
| ทุกปี (หรือตามที่บริษัทกำหนด) | ทบทวนทะเบียนกิจกรรม ประกาศ ระยะเก็บ ผู้ประมวลผลภายนอก และสิทธิ์ของบทบาทที่เห็นข้อมูลอ่อนไหว | หลายหน้า |

## 4. เมื่อเกิดเหตุละเมิดข้อมูล (เช่น ส่งไฟล์ผิดคน บัญชีถูกเข้าใช้ เครื่องหาย)
1. ผู้พบเหตุแจ้งเจ้าหน้าที่ PRV ทันที
2. เจ้าหน้าที่บันทึกเหตุในระบบ: เวลาที่พบ สิ่งที่เกิด ข้อมูลที่เกี่ยวข้อง จำนวนคนโดยประมาณ
3. ระงับความเสียหาย (เช่น ปิดบัญชี เปลี่ยนรหัส เรียกไฟล์คืน) แล้วบันทึกสิ่งที่ทำ
4. ประเมินความเสี่ยงต่อบุคคล (ต่ำ / กลาง / สูง / ยังไม่ทราบ) พร้อมเหตุผล
5. **ผู้มีความรู้ด้านกฎหมายตัดสิน** ว่าต้องแจ้งหน่วยงานกำกับและ/หรือเจ้าของข้อมูลหรือไม่ และภายในเวลาเท่าใด — ระบบนับเวลาตามค่า `privacy.breach_notify_hours` ที่บริษัทตั้งเท่านั้น
6. บันทึกวันที่แจ้งและเลขอ้างอิง (ถ้ามี) → ปิดเหตุพร้อมบทเรียนและมาตรการป้องกัน
> ไม่บันทึกข้อมูลส่วนบุคคลของผู้ได้รับผลกระทบลงในรายละเอียดเหตุ — ใช้จำนวนและประเภทข้อมูลแทน

## 5. หลักการเมื่อออกแบบหรือขอฟังก์ชันใหม่
- เก็บเท่าที่จำเป็น · ไม่เก็บข้อมูลชีวมิติหรือภาพลายเซ็นวาดบนเซิร์ฟเวอร์ (กฎของระบบ)
- ข้อมูลอ่อนไหว (สุขภาพ ศาสนา ประวัติอาชญากรรม ฯลฯ) ต้องมีเหตุผลและฐานที่ผู้มีความรู้ด้านกฎหมายยืนยัน และจำกัดคนเห็น
- ค่าเริ่มต้นเป็นส่วนตัว: ฟังก์ชันที่เปิดเผยข้อมูล (วันเกิด สมุดรายชื่อข้ามบริษัท แจ้งนิรนาม) ปิดไว้จนบริษัทเปิดพร้อมประกาศ
- ไม่ใส่ข้อมูลจริงบนเซิร์ฟเวอร์ทดลอง (InfinityFree)

## 6. สิ่งที่ระบบไม่ได้ทำแทน
- ไม่ตัดสินว่าใช้ฐานทางกฎหมายใด และไม่กำหนดจำนวนวันตามกฎหมาย
- ไม่ส่งแจ้งหน่วยงานกำกับให้อัตโนมัติ
- ข้อความประกาศที่ AI ร่างเป็นจุดตั้งต้นเท่านั้น
