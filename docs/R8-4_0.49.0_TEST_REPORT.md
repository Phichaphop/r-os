# รายงานผลทดสอบ — 0.49.0 (R8-4): การตรวจทานของ Payroll Checker + ภาษีหัก ณ ที่จ่ายของรางวัล

```
Release: 0.49.0   Environment: Local (เครื่องพัฒนาของ AI) + ระบบติดตั้ง blue_fresh7 (อัปเดตแล้ว — migration ใหม่ 1)   วันที่: 2026-11-21
ผู้ทดสอบ: AI (Claude)   ผู้ตรวจ: — (รอเจ้าของระบบ UAT)
เครื่องมือ: PHP 8.3 · MariaDB · PHPUnit 9.6.17 · PHPStan 1.12 · PHPCS 3.10 · Chromium (Playwright, CSP เปิดจริง) + axe-core 4.10
```

> **ที่มา:**
> - DEC-103 Q-11: "แต่งตั้ง Payroll Checker ภายหลัง เก็บประวัติแยกรายงวด"
> - DEC-103 Q-15: "ยังไม่มีสำนักงานบัญชี — AI ออกแบบการคำนวณ (อัตราให้ผู้ดูแลกรอกจากประกาศทางการ ไม่มีค่าเริ่มต้น)"
> - คำตอบผู้ใช้ 2026-11-21:
>   - ภาษีของรางวัล = "เครื่องคำนวณแยก (ไม่ผูกโมดูล)"
>   - การตรวจของ Payroll Checker = "ทีละรอบเงินเดือน"
> - บันทึกการตัดสินใจ DEC-118

> **สำคัญ:**
> - **ระบบไม่มีอัตราภาษีของรางวัล** ผู้ดูแลกรอกอัตรา (และมูลค่าขั้นต่ำ ถ้าประกาศกำหนด) จากประกาศทางการ ระบุแหล่งอ้างอิง แล้วอีกคนอนุมัติ
> - ตัวเลขในทดสอบและ e2e (5%, ขั้นต่ำ 1,000 บาท) เป็น**ค่าสมมุติ** ไม่ใช่อัตราจริง
> - วิธี "ผู้จ่ายออกภาษีแทน" (ทบกลับ) เป็นการออกแบบของ AI — ต้องให้ผู้รู้ภาษีตรวจก่อนใช้
> - การตรวจของ Payroll Checker เป็นการตรวจ**หลัง**อนุมัติ ไม่แทนการอนุมัติรอบเงินเดือน (ยังต้องมีผู้อนุมัติคนละคนกับผู้จัดทำ)

## ข้อควรรู้
- **การตรวจของ Payroll Checker ไม่เปลี่ยนผลหรือการจ่ายเงิน** ถ้าพบประเด็น ผู้จัดทำแก้ด้วยรอบแก้ไขหรือรอบเพิ่มเติม แล้ว Payroll Checker ตรวจรอบนั้นแยก
- รอบเดิมที่พบประเด็นตรวจซ้ำได้ เช่น บันทึกว่า "ถูกต้อง — แก้ด้วยรอบแก้ไข #n แล้ว" ทุกครั้งเก็บไว้
- **แต่งตั้ง Payroll Checker:** ผู้ดูแลระบบมอบบทบาท "ผู้ตรวจทานเงินเดือน (Payroll Checker)" ต่อบริษัท
  - เป็นบทบาทความเสี่ยงสูง ต้องมีผู้ดูแลอีกคนอนุมัติการมอบ
  - ผู้ที่ถือ PYO หรือ PYA ในบริษัทเดียวกันจะขึ้นรายงานขัดแย้งหน้าที่
- **บันทึกการตรวจไม่ควรมีจำนวนเงิน** ช่องบันทึกบอกไว้ ระบบไม่ส่งบันทึกเข้า audit หรือการแจ้งเตือน
- ยังไม่มีการแจ้งเตือนผู้จัดทำเมื่อพบประเด็น — ผู้จัดทำดูจากหน้าการตรวจทาน (กรอง "พบประเด็น")
- เครื่องคำนวณภาษีของรางวัลเป็นประมาณการ ไม่ออกหนังสือรับรองการหักภาษี และไม่ส่งข้อมูลไปไฟล์ยื่นภาษี
- ข้อมูลใน e2e:
  - รอบเงินเดือน ต.ค. 2569 (ทดสอบ e2e) ที่อนุมัติไว้ตั้งแต่ R8-1
  - อัตรารางวัล 5% ขั้นต่ำ 1,000 บาท เสนอผ่านเบราว์เซอร์โดย sysadmin2.demo แล้วอนุมัติด้วยสคริปต์ในชื่อผู้ดูแลอีกคน
  - e2e ทำงานสองรอบ (รอบแรกพบตารางล้นบนจอแคบ แก้แล้วรันใหม่) จึงมีการตรวจ 4 ครั้งในฐานข้อมูล e2e
