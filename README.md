# Blue OS — ระบบบริหารทรัพยากรองค์กร (เดิมชื่อ R-OS)

ระบบบริหารทรัพยากรองค์กรแบบ Modular Monolith (PHP 8 + MySQL/MariaDB) — เอกสารออกแบบอยู่ในโปรเจกต์ claude.ai "R-OS Project" (`R-OS_Phase0/`, `R-OS_Spec_Pack_v22/`)

> **สถานะ:** R5 (0.41.0) แชท M17 — ล่าสุด · R4 (0.40.0) แข่งเป็ดแบบภาพเข้าเส้นชัย + บริษัทตัวอย่างครบทุกฝ่าย · R3 (0.39.0) เครื่องมือ PDF + เซ็น PDF · R2 (0.38.0) QR Code · R1 (0.37.0) ชื่อระบบ Blue OS · แผนถัดไป R2–R9 (DEC-103) · เฟส 9 ส่งถึง 9E-2 (0.36.0) · ก่อนหน้า: เฟส 4B (0.6.0) — เวลาทำงาน (M34) + ตัวรับเวลาจำลอง + Punch API · ต่อจาก 4A (พนักงาน + การลา) และเฟส 1–3U · บัญชีเป็น **Demo only** (DEC-50) · **ข้อมูลจำลองเท่านั้น** บน Prototype (DEC-34, DEC-46)

  - **จัดหน้า:** ลากเพื่อเรียงใหม่ (หรือใช้ปุ่ม ‹ ›), กด ⟳ เพื่อหมุน และเอาเครื่องหมาย "เก็บ" ออกเพื่อลบหน้า
  - **รวม PDF / รูปเป็น PDF:** ลากการ์ดไฟล์เพื่อเรียงลำดับ
  - **ดึงหน้า / หมุน / ลายน้ำ / เลขหน้า:** แตะภาพหน้าเพื่อเลือก ระบบเติมช่อง "หน้า" ให้
  - ผลลัพธ์แสดงเป็นภาพเช่นกัน
  - ถ้าเบราว์เซอร์ปิดสคริปต์ ช่องตัวเลขและตัวเลือกแบบเดิมยังใช้ได้
- **ไม่เก็บไฟล์จนกว่าจะกดบันทึก** (ข้อ 8.2):
  - ไฟล์ต้นฉบับถูกลบทันทีที่ได้ผลลัพธ์
  - ผลลัพธ์ที่ยังไม่บันทึกอยู่ได้ `pdf.result_minutes` นาทีเพื่อให้ดาวน์โหลด (ค่าเริ่มต้น 60 ผู้ดูแลปรับได้ 10–1440) แล้วระบบลบทิ้ง
  - งานที่ไม่ได้บันทึกไม่ขึ้นในรายการ รายการ "ผลลัพธ์ที่บันทึกไว้" แสดงเฉพาะงานที่กดบันทึกเข้าทะเบียนเอกสารแล้ว
  - ค่า `pdf.temp_hours` เลิกใช้แล้ว
- **เซ็น PDF** (`/pdf/sign`, ข้อ 3.1):

  - ดาวน์โหลดเป็น PNG พื้นโปร่งใส หรือคัดลอกเป็น Base64 (data URI)
  - วางลงบน PDF จากเครื่องได้ทุกหน้า รวมหน้าที่หมุนไว้: แตะเพื่อวาง ลากหรือใช้แป้นลูกศรเพื่อย้าย ปรับขนาด แล้วดาวน์โหลดไฟล์ที่เซ็นแล้ว
  - **ทำในเบราว์เซอร์ทั้งหมด:** หน้านี้ไม่มีฟอร์มและไม่มีคำขอที่ส่งลายเซ็นหรือ PDF ไปเซิร์ฟเวอร์ และไม่เก็บไว้ในเบราว์เซอร์

2. ไฟล์สำรองอยู่ที่ `storage/backups/` (ปิดจากเว็บ, ไม่อยู่ใน zip/git) — ตั้ง `BACKUP_OFFSITE_PATH` ใน `config/env.php` ถ้ามีที่เก็บภายนอก หรือดาวน์โหลดเก็บเองเป็นระยะ
3. Restore drill ต้องใช้ฐานข้อมูลแยก `<ชื่อฐานข้อมูล>_drill` (หรือ `BACKUP_DRILL_DB`) — บน XAMPP (ผู้ใช้ root) ระบบสร้างให้เอง · ถ้าผู้ใช้ฐานข้อมูลไม่มีสิทธิ์สร้าง ให้สร้างเองแล้วให้สิทธิ์ผู้ใช้เดียวกัน (ไม่มีสิทธิ์ → drill ขึ้น "ติดขัด" ไม่ใช่ "ผ่าน") · บน InfinityFree สร้างฐานข้อมูลที่สองใน vPanel แล้วใส่ชื่อเต็มใน `BACKUP_DRILL_DB`
4. ไปที่เมนู **สำรองและกู้คืนข้อมูล** → "เริ่มสำรองข้อมูล" → เมื่อขึ้น "ตรวจแล้ว" เปิดชุดนั้นแล้วกด "ซ้อมกู้คืน (ฐานข้อมูลแยก)" — นี่คือหลักฐาน TC-DR ของเครื่องนั้น

**อัปเกรดจากเฟส 3A → 3B:** ทำแบบเดียวกับด้านล่าง (แตก zip ทับ → อัปเดตฐานข้อมูล) — ไฟล์เอกสารจะเก็บที่ `storage/documents/` (ปิดการเข้าถึงจากเว็บแล้ว) ให้รวมโฟลเดอร์นี้ในการสำรองข้อมูลด้วย

**อัปเกรดจากเฟส 2 → 3A (ไม่ต้องติดตั้งใหม่):** แตก zip ทับโฟลเดอร์เดิม (ไฟล์ `config/env.php` และ `storage/` ไม่อยู่ใน zip จึงไม่ถูกทับ) → เข้าสู่ระบบด้วยบัญชีผู้ดูแล → ระบบพาไปหน้า **อัปเดตฐานข้อมูล** → Export ฐานข้อมูลจาก phpMyAdmin เก็บไว้ก่อน แล้วติ๊กยืนยัน → กด "อัปเดตตอนนี้" → ยืนยันรหัสผ่าน → กดอีกครั้ง

**อัปเกรดจากเฟส 1:** ต้องติดตั้งใหม่บนฐานข้อมูลว่าง — ลบโฟลเดอร์เดิม (หรือลบ `config/env.php` และ `storage/install.lock`), DROP แล้วสร้าง `blue_dev` ใหม่, แล้วเปิด `/install` อีกครั้ง

**หลังติดตั้ง:** ยืนยันตัวตนขั้นที่ 2 (MFA) ปิดอยู่เป็นค่าเริ่มต้น — เปิดได้ที่เมนู **ความปลอดภัย** (ต้องยืนยันรหัสผ่านซ้ำ + ระบุเหตุผล); เมื่อเปิด ให้เพิ่มบัญชีในแอป authenticator แบบ "ป้อนคีย์เอง" (ยังไม่มี QR code) · ถ้าเลือกข้อมูลตัวอย่าง รหัสผ่านของผู้ใช้ตัวอย่างทั้ง 10 คน (ใช้รหัสเดียวกัน) จะแสดงครั้งเดียวที่หน้าติดตั้งเสร็จ · อีเมลเปิดใช้งาน / OTP ดูได้ที่ `/system/mailbox` · ธีมเริ่มต้นเป็นแบบสว่าง (กดไอคอนพระจันทร์เพื่อสลับ — ระบบจำค่าไว้ในเบราว์เซอร์)

## ขึ้น InfinityFree (Prototype — ข้อมูลจำลองเท่านั้น)
1. สร้าง MySQL database ใน vPanel
2. รัน workflow **Deploy prototype** ใน GitHub Actions (ต้องตั้ง secrets `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`, `FTP_SERVER_DIR`) — หรืออัปโหลดทั้งโฟลเดอร์ (ยกเว้น `vendor/`, `tests/`) ไปที่ `htdocs/` หลังรัน `php bin/blue assets:publish`
3. `.htaccess` ที่รากจะส่งทุกคำขอไป `public/` และ**ปิด** `core/ config/ storage/ …` (ทดสอบกับ Apache แล้ว — ดูรายงานทดสอบ) — ต้องตรวจซ้ำบนโฮสต์จริงหลังอัปโหลดครั้งแรก
4. เปิดเว็บ → `/install` → ใส่รหัสจาก `storage/locks/setup-code.txt` (เปิดผ่าน File Manager)

## คำสั่ง CLI
```
php bin/blue migrate [--backup-confirmed] [--approve-destructive]   # Staging/Production ต้องยืนยัน backup
php bin/blue migrate:status        # applied / pending / DRIFT (ไฟล์ migration ถูกแก้)
php bin/blue jobs:run              # cron ทุกนาที (Staging/Production)
php bin/blue assets:publish
php bin/blue check:all             # TC-AI-00, secret scan, token lint, architecture
```

## ทดสอบ
```bash
composer install                          # phpunit 9.6, phpstan, phpcs (dev เท่านั้น — runtime ไม่ต้องใช้ vendor/)
BLUE_TEST_DB_NAME=blue_test vendor/bin/phpunit
vendor/bin/phpstan analyse && vendor/bin/phpcs && php bin/blue check:all
```
CI (`.github/workflows/ci.yml`) รันทั้งหมดนี้บน PHP 8.1 และ 8.3 กับ MariaDB 10.11 ทุก push/PR และเก็บผลเป็นหลักฐาน

## กติกาที่โค้ดบังคับ
- schema เปลี่ยนผ่าน migration เท่านั้น — **ห้ามแก้ไฟล์ migration ที่รันแล้ว** (ระบบจะขึ้น DRIFT และหยุด) ให้เพิ่มไฟล์ใหม่
- view ห้ามมี SQL; เวลาอ่านผ่าน `Clock`; โมดูลห้ามใช้ Infrastructure ของโมดูลอื่น (`bin/blue check:arch`)
- สีใช้ semantic token เท่านั้น ไม่มี HEX นอก `ui/tokens/`, ไม่มี inline style/script ที่ไม่มี nonce (`check:tokens`)
- ไม่มีการเรียก AI ใน rollout 1 (`check:ai`)
- ไม่ใส่ค่ากฎหมาย/อัตราตายตัวในโค้ด — เป็นค่า config ที่มีผู้อนุมัติ (เฟส 3)
- รายงานผลทดสอบเป็น `PASS / FAIL / NOT RUN / BLOCKED / REVIEWED ONLY` ตามจริง
